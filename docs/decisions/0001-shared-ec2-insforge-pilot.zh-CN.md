# 生产决策记录：InsForge 控制面与共享 EC2 试点

[English](0001-shared-ec2-insforge-pilot.md)

**状态：** 接受用于有界赞助方试点；晋级生产仍需通过门槛
**日期：** 2026-09-12
**负责人：** FlowWitness 维护者
**复审触发：** 首次外部双版本试点完成后，或开始接收敏感客户数据前

## 决策

下一轮托管验证使用现有共享 AWS EC2 主机执行浏览器任务。FlowWitness 以
独立的非特权服务运行在 `4310` 端口，与现有 DSH 服务并行；DSH 继续使用
`3080` 端口。

InsForge 继续作为控制面和事实来源，负责应用状态、任务、认证以及私有的
`flowwitness-private` 制品 bucket。当前 InsForge Compute 地址在 EC2 验证期间
保留为回退路径。本次试点不需要付费 InsForge Compute、新 EC2、新 EBS、
新 S3 bucket 或远程浏览器供应商。

现有 EBS 只作为共享主机的本地临时空间。截图、上传文件和视频在制品适配器
接入后应存入对象存储；EBS 不是跨主机存储接口。普通 gp3 盘保持挂载在一台
主机上，不能同时挂载到多个 EC2 实例。

## 范围与运行形态

试点服务启用后采用以下边界：

| 平面 | 共享资源 | 边界 |
| --- | --- | --- |
| API 与状态 | InsForge 项目及当前托管地址 | InsForge RPC 与现有认证保持权威 |
| 浏览器执行 | 现有 `flinter-orca-dsh` EC2 主机 | 独立 FlowWitness 服务，端口 `4310`，一次只运行一个回放 |
| 本地临时空间 | 主机根 EBS 盘 | 仅临时浏览器文件；必须使用私有目录并清理 |
| 持久制品 | InsForge `flowwitness-private` bucket | 私有对象 key 与按范围元数据；不能公开 bucket |
| 公网访问 | 临时出站 Cloudflare Tunnel | 不新增入站安全组规则或自定义域名 |

FlowWitness 单元必须使用 `ubuntu` 身份、私有数据目录和明确的内存/任务限制
（初始目标：`MemoryMax=900M`，浏览器任务最多一个）。不得停止、替换或重配
DSH 单元。客户凭据和敏感客户数据不在本试点范围内。

## 决策证据

2026-09-12 的只读检查确认：

- 共享主机是 Ubuntu 22.04.5 ARM64 `t4g.small`，2 vCPU、2 GiB 内存和一块
  40 GiB gp3 根盘；没有第二块挂载的 EBS。
- SSM 在线。主机已有 `dsh.service` 和监听 `127.0.0.1:3080` 的 Node 服务；
  未安装 Docker。
- DSH 运行时主机约有 1.1 GiB 可用内存。真实 Playwright 1.63 ARM64
  Chromium 烟囱测试使用与 FlowWitness 相同的低内存启动参数，成功启动、
  导航、点击、断言并保存 PNG。
- InsForge 项目已有私有且为空的 `flowwitness-private` bucket。当前 FlowWitness
  制品代码仍把字节存入私有状态快照，因此 bucket 交付是后续实现，不是已完成
  的能力。详见 [PLATFORM.md](../PLATFORM.md#insforge-boundary)。
- 当前托管 InsForge Compute 是免费的 512 MB `shared-1x`；API 和状态检查通过，
  但内置 Chromium 不能稳定创建页面。详见 [HOSTED-BACKEND.md](../HOSTED-BACKEND.md)。

## 为什么这是最低承诺路径

它保留现有后端和回退路径，使用已有计算和存储，并在增加供应商协议或持续付费
规格前先验证真实浏览器闭环。共享通过进程边界、端口、单任务租约、内存限制和
私有对象路径控制，而不是让多台主机共享同一文件系统。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| DSH 与 Chromium 争用 2 GiB 内存，且无 swap | 一次一个回放、`MemoryMax`、清理，并在接收外部数据前观察内存/OOM |
| 主机带有旧 DSH 权限 | 使用 `ubuntu`、只用合成数据、不改 DSH；生产前审查并替换主机角色 |
| 根 EBS 未加密且终止实例时会删除 | 仅作临时空间；持久制品放在私有对象存储，后续生产主机使用加密盘 |
| 主机没有 Docker 且安全组无入站规则 | 试点使用直接 Node 服务，通过 SSM 和临时出站隧道管理 |
| 制品字节可能让 InsForge 状态快照膨胀 | 大型录制或视频前完成私有 bucket 适配器 |
| 共享执行不等于生产隔离 | 保持单应用、仅用于试点；生产前必须通过下列门槛 |

## 晋级生产前的验收门槛

1. 独立 FlowWitness 单元启动，并通过认证健康、设置、图片、模块和私有制品
   检查，同时不改变 DSH 行为。
2. 托管版本 A/B 浏览器闭环通过，包括旧答案撤回、修复、脱敏截图和明确发布。
3. 重启后 InsForge 状态保留，且仍能交付有范围的私有制品。
4. 记录签名 GitHub 推送、客服绑定、中英文响应和首次外部双版本试点。
5. 形成内存、冷启动、错误和清理观测，并据此决定常驻或按需停止策略。
6. 接收生产数据前，替换旧主机权限、使用加密存储、完成备份恢复与告警，
   并确定租户/保留策略。

## 回滚

只停止 FlowWitness 服务并删除其临时代码/数据目录。保留 `3080` 上的 DSH、
InsForge 项目、当前托管地址和 EBS 挂载。FlowWitness 回滚不应分离或删除该盘。

## 延后的替代方案

- 付费 InsForge Compute：等共享主机试点失败或持续使用证明需要后再考虑。
- 远程浏览器适配器：等真实采用者需要供应商隔离或托管浏览器扩容后再做。
- 独立加密 EC2：属于生产加固选项，不是首轮试点前置条件。
- AWS S3：在完成 InsForge bucket 适配并测量保留需求后，作为可选对象存储迁移。

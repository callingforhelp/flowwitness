# FlowWitness 发布主线

**状态：** 正在执行
**负责人：** FlowWitness 维护者
**更新：** 2026-09-12

这份计划把一次真正的产品发布路径放在基础设施扩张和第二阶段功能之前。
目标是让一个伙伴使用一个无敏感信息的预览应用和一个客户流程。

## 首次发布范围

首次发布是一个窄而完整的服务，不是通用代理平台：

- 一个伙伴拥有的预览应用；
- 一个包含角色、源文件、选择器和预期结果的明确 workflow；
- 一个稳定的 HTTPS FlowWitness 地址；
- 现有共用 EC2 上一个有界 Chromium worker；
- 使用 InsForge 保存流程状态、问题、发布记录和私有证据；
- 一个调用 `/v1/query` 的已有客服后端。

完整主线是：

```text
Git push
  → 签名 webhook 和有范围的影响问题
  → 操作员解决问题
  → 在批准的预览中执行有界 Chromium 回放
  → 私有证据
  → 明确发布
  → 客服查询返回匹配版本的中英文指引
```

## 执行顺序

| 顺序 | 工作 | 完成证据 | 状态 |
| --- | --- | --- | --- |
| 1 | 可重复的发布 smoke | `npm run smoke:launch` 无副作用地检查健康、认证边界、操作台、部署身份、已验证流程、中英文客服答案和私有证据。 | **本次已实现** |
| 2 | 稳定试点入口 | 固定 HTTPS 地址、重启策略和运行说明；无账号 quick tunnel 不再用于伙伴。 | 未完成；当前 tunnel 仅用于演练 |
| 3 | 真实客服连接 | 一个已有聊天/后端保管 support 凭据和可信会话绑定；不新建聊天产品。 | 未完成；接口契约已有 |
| 4 | 外部两版本试点 | 版本 A 发布、版本 B 改 UI、旧答案撤回、失败回放证据、修复发布、中英文查询和保留/延迟指标。 | 未完成；合成 Pilot 02 不满足此门槛 |
| 5 | 发布加固 | 备份/恢复、告警、保留策略、内存/冷启动观察和操作手册。 | 未完成；首轮继续使用现有 EC2/InsForge |
| 6 | 选择第二阶段 | 根据实际试点失败选择复现或视频。 | 等第 4 项有证据后 |

## 明确暂缓

在主线有伙伴和指标前，不增加付费计算、远程浏览器供应商、多租户、新聊天产品、
常驻代理群、视觉理解、电脑操作、调度器、Archify 导出或生产视频交付。这些功能
仍保留为独立的第二阶段或后续决策，并没有删除。

## 发布验收

满足以下条件后，才能让受控伙伴使用首次发布：

1. 新 checkout 可以对选定地址运行只读 launch smoke，且不打印凭据。
2. 一次真实签名 push 为伙伴 workflow 创建一个有范围的审核问题，重复 delivery
   会被忽略。
3. 版本 A 和版本 B 都有浏览器收据和私有截图。
4. 当前版本不会返回旧指引；明确请求旧版本时仍返回对应指引。
5. 现有客服后端可以用中英文读取修复后的发布记录。
6. 重启后记录和私有证据仍在，并记录配置时间、修复时间、冷热延迟、正确性、误报、
   保留结果和是否继续启用的反馈。

在伙伴完成清单前，应称 FlowWitness 为托管试点后端和本地 alpha，不能称为生产基础设施。

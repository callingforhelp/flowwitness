# 外部试点清单

这份清单面向一个无敏感信息的预览应用，用来执行第一阶段“改动到答案”闭环。
不使用客户生产数据、凭据或自动控制电脑。试点用于收集证据，不等于生产认证。

## 首次运行前

- 确定一个应用负责人和一个客户经常询问的管理员流程。
- 提供带可丢弃种子数据的预览/测试来源。不要使用生产账号、客户个人信息、支付
  数据或可复用凭据。
- 增加部署身份接口，返回
  `{"version":"<发布版本>","source_revision":"<提交>"}`。
- 编写并校验一个流程，包含稳定步骤 ID、源文件、无敏感选择器、预期结果，以及需要
  时的中英文文本。
- 选择已有客服聊天或后端调用 `/v1/query`。客服令牌只放在该后端，不放到浏览器小部件。
- 与应用负责人一起检查 `redact_selectors` 和图片同意范围。

## 版本 A

1. 导入流程并设置预览部署身份。
2. 执行真实浏览器验证，逐张检查截图。
3. 解决生成的问题并明确发布该运行。
4. 让客服后端用中英文询问同一个已知问题。
5. 记录首次配置时间、热查询延迟、答案正确性和制品过期情况。

## 版本 B 的改动与修复

1. 做一次可见的 UI 改动，移动或重命名已记录的控件。
2. 通过 GitHub webhook 推送提交；若 webhook 内容不完整，则用 CLI 对完整 base/head
   范围执行 impact。
3. 确认新的部署身份不会返回旧的已发布答案。
4. 对改动后的预览执行验证并保留失败证据。
5. 修复流程，再次验证、解决新问题并明确发布修复版本。
6. 再次询问相同的客服问题，确认只返回修复后的步骤；显式请求旧版本时仍返回对应指引。

## 完成证据

出现两个版本收据、旧答案撤回收据、修复发布收据、中英文客服查询收据，以及私有制品
访问/过期检查后，试点才算完成。记录：

- 首次配置和修复流程分别需要多少分钟；
- 热启动和冷启动查询延迟，并单独标出冷启动；
- 相关与无关的影响提醒；
- 客服答案是正确、需要澄清还是不可用；
- 截图保留、脱敏和删除/过期结果；
- 操作员反馈及负责人是否愿意继续启用流程。

如果需要生产凭据、个人信息、无限网络访问或控制客户电脑，应停止试点，并把需求另列为
第二阶段提案。

当前托管服务仍有 512 MB 浏览器容量门槛和 scale-to-zero 冷启动策略。在解决前，浏览器
步骤应在本地或获批准的浏览器工作进程执行；托管服务只用于认证 API/状态部分。

# Reproduction

`createModule({repository,jobs,browser?,clock?,config?})` has no import-time I/O. `create(operator,input)` returns `{item,job}`; `get(principal,{id})` returns `{item}`. HTTP ownership is POST `/v1/reproductions` (202) and GET `/v1/reproductions/:id` (200). Unsupported methods return 405; unrelated paths return null. Exceptions use platform error codes and are serialized by the coordinator.

Creation requires `issueId`, `idempotencyKey`, `approvalRef`, `target:{origin,environment,revision}`, and a nonempty `steps` array. An authenticated operator's submission is the approval assertion; the browser adapter must resolve that approval reference against its trusted approval registry before starting a VM. The issue must exist in the exact application and conversation. Reusing a key returns the same job; changed canonical input conflicts. Customers need a conversation binding and receive only base fields, issueId and jobId. Agents can read and execute but cannot approve/create.

Targets accept HTTP(S) origins without credentials, paths, queries or fragments and environment `preview` or `test`. Production is rejected. Limits default to `{concurrency:1,maxDurationMs:600000,maxActions:50}`; callers can lower duration/action caps. Only `click` and `assertVisible` with a selector, `screenshot` without arguments, and `navigate` with a same-origin absolute path are accepted. Navigation queries/fragments, executable scripts, typing values, arbitrary fields and caller-provided session secrets/references are rejected. Selectors, paths, revision and approval IDs must contain only non-secret identifiers. This initial implementation deliberately does not support entering credentials or text.

## Worker adapter

The coordinator first claims a browser-capable reproduction job through the jobs facade, then calls `run(agent,{id:reproductionId,token:job.lease.token,signal?})`. This method consumes an existing lease; it never claims unrelated jobs. Missing browser support yields 503 while create/get remain available.

Implement `browser.start({scope,target,approvalRef,limits,signal})`, returning a fresh session with `step(step,{signal})`, optional `stop()` and `destroy()`. The adapter must validate approval against exact scope/target/revision, resolve any session secrets internally, reject production or unapproved targets and cross-origin redirects, enforce hard duration/action caps, and clean up partially created VMs on startup failure. It must honor AbortSignal and stop/destroy calls. The coordinator/adapter must atomically reserve one VM per application across processes; the module additionally prevents concurrent runs per application within its own instance. Multiple module instances alone are not a distributed semaphore.

The worker heartbeats before and after each action and every 20 seconds (config.heartbeatMs can lower this), races browser operations against timeout/cancellation, and stops/destroys on exit. Lease loss fails closed. Raw browser output is discarded. Evidence contains only action index/type/completed receipts, no artifact IDs, and is always `unverified`; recording is not validation or publication. A final fenced jobs.complete accepts the evidence reference. Failed completion removes the temporary bundle when possible and attempts fenced jobs.fail with a generic error code. Artifact capture/upload and trusted verification are separate future integrations. Adapters must never log session secrets.

Run `node --test test/reproduction.test.mjs` for independent in-memory fixtures. These tests do not prove deployed E2B behavior or distributed reservation.

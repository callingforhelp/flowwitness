Keep workflows in Git

The specification connects source files, screens, steps, and evidence. Start with three to five important customer workflows.

Withhold outdated steps

The working demo enforces release and role checks. Stale or failed evidence produces no actionable answer. Production verification remains planned.

Make uncertainty visible

The demo asks for clarification on unknown questions and unsupported roles. It uses a fixed synthetic fixture, not an AI model.

Stage 1 / Planned foundation

Make the core loop trustworthy.

Implement Git-tracked workflows, source relationships, change detection, build-specific sandbox verification, and basic agent-readable guidance. Define screenshot-plus-question intake with clarification for ambiguous context.

Screenshot intake is a contract, not working image understanding. The current demo does not accept or analyze images.

Stage 2 / Future exploration

Richer ways to help.

Explore narrated walkthrough videos, broader image understanding, and customer-side execution with explicit consent. These capabilities are planned, not available today.

What support would unlock

The first milestone: one local end-to-end fixture connecting a source change to a stale workflow, an actual browser verification run, and a version-matched answer with saved evidence.

Engineering support would help build that loop. A pilot partner could contribute one non-sensitive SaaS workflow and evaluate whether the evidence and fallback answers are useful. Scope and acceptance criteria would be agreed before a pilot; there is no delivery date or outcome guarantee.
